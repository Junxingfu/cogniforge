# 首页滚动后切换训练库无明显反应

日期：2026-10-27。使用最新目录 `/Users/fujunxing/IdeaProjects/cogniforge`，没有恢复或修改旧路径。

## 复现证据

在桌面浏览器首页向下滚动，window.scrollY=720，训练卡片标题距视口顶部约16.6px。点击侧栏训练库，页面状态和导航选中均已改变，但scrollY仍为179.5，训练库标题仍距顶部约16.4px。首页与训练库复用同组卡片，浏览器滚动锚定把卡片留在相同视觉位置，因此用户认为没有响应。

## 排查

1. 预测：缺少滚动重置时，切换状态成功但卡片视觉位置不变。浏览器观察支持此项。
2. 预测：共享内容加重无变化感。两页的同一训练卡片区域、截图支持此项。
3. 预测：导航被训练状态禁用或点击丢失。复现时按钮启用且状态成功改变，排除作为本次根因。

## 修复

App统一navigate入口，在Vue提交目标DOM后重置window滚动为0，再保证内容焦点可读（focus使用preventScroll）。侧栏、品牌链接、首页CTA、重复点击当前页采用一致语义。进入训练说明页也回顶部。“返回训练库”不再仅清空active，而是明确进入训练库。main不再垂直auto居中；移动端导航保持可见，使用aria-current标记当前页面。

分析模式、档位与训练设置拆开；每项任务分别记住本轮页面生命周期内的参数选择，避免查看复测后误入复测训练。存储到跨刷新偏好不是本轮功能。

## 验证

- 先运行真实App挂载测试：侧栏、首页CTA、任务打开/返回、重复当前导航4例均失败（无滚动调用）。
- 修复后同4例通过，另补分析设置隔离测试。
- 浏览器原场景复测：滚动872.5px → 点击训练库 → scrollY=0、焦点MAIN、标题训练库。
- 浏览器切换n-back参数1→2后，项数31→32、示例A→A变为A→B→A；返回后header为训练库，scrollY=0。
- 使用独立H2内存数据库进行浏览器核验，未改动已有训练记录。

## 预防

页面状态不仅是一个字符串，还包含滚动、焦点和退出目的地。后续页面通过统一入口切换；新增页面需要覆盖“长页面底部进入”的用户旅程。暂不为这次问题引入路由框架；需要URL、前进后退时再迁移到路由并保持这些验收条件。
